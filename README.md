## Languages and URLs

The language of a page is decided by its URL, not by the browser or a saved preference. The root is Italian (`/`, `/pdf-tools`); the English versions live under `/en/` with the same slugs (`/en/`, `/en/pdf-tools`). Every page is prerendered in its own language, with `<html lang>`, title, description, Open Graph tags, `canonical` and `hreflang` links (`it`, `en`, and `x-default` pointing to English). `public/sitemap.xml` lists all of them with `xhtml:link` alternates. Each tool has its own 1200×630 social image per language (`public/og/<lang>/<slug>.png`, generated by `npm run og-images`), used for `og:image` and `twitter:image`; the home pages use `public/og-image.png`.

Tools that only make sense in Italy (codice fiscale, IBAN & partita IVA, e-invoice, VAT & withholding calculator) are flagged `italyOnly` in the registry: they have no `/en/` page, the EN switch is disabled on them, and the English home links to them in a discreet line. An unknown `/en/...` address goes to `/en/`. Visitors whose browser is not in Italian get a small, dismissible hint on Italian pages that have an English version; there is no automatic redirect.

## Tools

The home page groups the tools by category, with filter pills (shareable as `?categoria=sviluppatori`, or `?category=developers` on the English home) and a search box (press `/` or `Ctrl+K` / `⌘K` to jump to it).

### Hash & checksum

![Hash & checksum](docs/screenshots/hash-generator.png)

### PDF to text

### IP subnet calculator (CIDR)

- Route `/subnet-calculator`. IPv4 as `a.b.c.d/24`, `a.b.c.d 255.255.255.0` or alone (/32); IPv6 as soon as there is a colon. Network, broadcast, hosts (/31 per RFC 3021, /32), mask, wildcard, class and type, and the binary form with the network bits highlighted.

### docker run to docker-compose

- Route `/docker-run-to-compose`. The shell tokenizer is shared with the cURL converter (`src/app/shared/shell-tokenize.ts`). Several commands (one per line, `;` or `&&`) become several services; named volumes go in the `volumes:` section and non-default networks in `networks:` as `external`, with a note.

### CSS clamp() fluid typography generator

- Route `/css-clamp-calculator`. Sizes in px or rem (configurable root size) between two viewports; output in rem. The type scale multiplies the base size by a ratio per step (separate ratios at the minimum and maximum viewport) and exports `--step-N` variables.
- The preview computes the size for a simulated width. A warning appears when max/min is above 2.5 (WCAG 1.4.4, Resize Text), as a rule of thumb rather than a guarantee.

### Time calculator (hours and minutes)

- Route `/time-calculator`. Durations in `1:30`, `01:30:15`, `1h 30m`, `90m`, `1,5h` and more, one per line (`-` subtracts, `#` starts a comment); unitless numbers are hours or minutes as chosen.
- Timesheet lines `[day] start end [break]`; an end before the start crosses midnight and counts on the day it started. Overtime is the part above a per-week or per-day threshold; the amount uses integer arithmetic (BigInt) with an optional overtime premium.

### Invoice due dates (Italian only)

- Route `/scadenze-fatture`, with no `/en/` version. "Invoice date", D.F.F.M. (days added, then moved to the end of the month, plus optional extra days) or end of month + days. Installments split the total in equal amounts rounded down to the cent, the last one takes the difference.
- Moving to the next business day is optional and shown in the table; Italian national holidays (Easter computed for each year) come from the working-days tool. The legal-terms note (D.Lgs. 231/2002) is informational, with no late-payment interest. CSV and iCalendar (.ics, one all-day event per due date).

### Fake tax code and VAT number generator (Italian only)

- Route `/generatore-codice-fiscale`, with no `/en/` version. A warning on top says the codes are made up and only for tests: they have the right format and check digits but belong to nobody, and must not be used for official purposes, to sign up to services or to impersonate someone.
- Tax codes are computed with the official rules (the same code as the tax code tool) on a made-up first name, surname, sex, birth date and birthplace taken from the fake data lists, so every row is coherent with its code and accepted by the validator. Filters: sex, exact date or range of years (1900 to this year), comune or foreign state with the same search box as the tax code tool (the list of places is loaded only when you pick one). Homocodia: a fixed level from 1 to 7 or a random one, applied with the replacement rules and a recomputed check character.
- VAT numbers: 7 digits of progressive, 3 of provincial office (picked from the list of historical province codes or random) and the check digit. There is no natural person / company option because the Italian VAT number format does not distinguish them (explained in the FAQ).
- The seed is optional: the same seed and options always give the same results. The share link holds only the options (quantity, filters, seed), never the generated codes. Copy of a single value or of all, CSV and JSON download, "Send to" the tax code and IBAN / VAT validators, and links to both validators.

### Encrypt and decrypt files

![Encrypt and decrypt files](docs/screenshots/file-encrypt.png)

- Route `/file-encrypt` (also `/en/file-encrypt`). Files (up to 256 MB, the whole file is processed in memory by WebCrypto without freezing the page) or text, with a passphrase typed twice when encrypting.
- AES-256-GCM with a key from PBKDF2-HMAC-SHA256 (600,000 iterations, 16-byte random salt) and a random 12-byte IV. Format `.rrenc`: `RRENC` (5 bytes), version (1), iterations (4, big-endian), salt (16), IV (12), ciphertext and 16-byte GCM tag; the 38-byte header is authenticated data. Text uses the same bytes as Base64.
- A wrong passphrase and a tampered file give the same clear message (GCM cannot tell them apart); files declaring fewer than 600,000 iterations are refused. The passphrase is NFC-normalised. The file name is not stored: decrypting strips `.rrenc`.

### Barcode generator

![Barcode generator](docs/screenshots/barcode-generator.png)

- Route `/barcode-generator` (also `/en/barcode-generator`). `jsbarcode`, loaded on demand: EAN-13, EAN-8, UPC-A, Code 128, Code 39 (optional modulo 43), ITF-14, ITF, Codabar, MSI and Pharmacode.
- Each format has its own validation; for EAN, UPC and ITF-14 the check digit is added when missing and verified when present (the error says which digit is expected). Options: bar width, height, text and size, margin, colours.
- Download as SVG or as PNG (1x to 4x); the bulk mode reads one value per line (up to 300), reports the lines with errors and builds a ZIP of SVG or PNG files with `fflate`.

### QR code reader

![QR code reader](docs/screenshots/qr-code-reader.png)

- Route `/qr-code-reader` (also `/en/qr-code-reader`). Reads an image chosen, dropped or pasted (`Ctrl+V`) with `jsQR`, trying several sizes so small codes inside big photos can be found, or the camera (`getUserMedia`) in a light loop at about 8 frames per second.
- The camera starts only after pressing the button and its tracks are stopped when a code is found, on Stop, when the tab goes to the background and when leaving the page.
- The content is classified (URL, Wi-Fi, vCard, email, phone, SMS, location, otpauth, calendar event, text) and shown as text. URLs get warnings (http, user name before `@`, punycode, IP address, shortener, unusual port) and open only through an explicit button with `rel="noopener noreferrer nofollow"`; `javascript:`, `data:` and other schemes are never linkable. Wi-Fi passwords are hidden until revealed.

### Sort lines

![Sort lines](docs/screenshots/sort-lines.png)

### Find and replace

![Find and replace](docs/screenshots/find-replace.png)

- Route `/find-replace` (also `/en/find-replace`). Plain-text mode (everything literal, `$` is not special) or regex mode (flags g, m, s, u; `$1`, `$<name>`, `$&`), case sensitivity and whole-word matching, up to 20 rules applied in sequence that can be turned off or reordered.
- A preview highlights the matches of the chosen rule on the text it receives, with a count for every rule; the final result can be copied, downloaded or reused as the source.

### Text to speech

![Text to speech](docs/screenshots/text-to-speech.png)

### Italian tax code (codice fiscale)

![Italian tax code](docs/screenshots/codice-fiscale.png)

- Calculation with the official rules (surname and name consonants, the 1st/3rd/4th consonant rule for names, month letters, day + 40 for women, cadastral code, check character); accents, apostrophes, spaces and compound surnames are handled.
- Birth place: municipality with a type-ahead combobox (ARIA pattern), or the cadastral/Z code typed by hand.
- Check and decode: length, structure, check character, sex, birth date (most plausible century plus the alternative) and place; omocodia (letters LMNPQRSTUV in place of digits) is supported in both directions and the seven omocodia variants are listed.
- The result is the "theoretical" code: the real one is assigned by the Agenzia delle Entrate. Nothing is sent or stored.
- Place data: ISTAT "Codici dei comuni, delle province e delle regioni", CC BY 4.0, saved in `public/data/luoghi.json` (about 220 kB, 74 kB gzipped, loaded only when needed) by `node scripts/update-places.mjs`. Abolished municipalities and foreign countries (Z codes) have to be exported from ISTAT's SITUAS portal and passed with `--soppressi` and `--esteri` (see the script header); until then the Z code can be typed by hand.

### Italian e-invoice viewer (FatturaPA XML/P7M)

![Italian e-invoice viewer](docs/screenshots/fattura-elettronica.png)

- Route `/fattura-elettronica`. Opens `.xml`, `.p7m` (CAdES, DER or Base64) and `.zip` files with several invoices. For `.p7m` a small ASN.1/DER reader (definite and indefinite lengths, fragmented OCTET STRINGs) extracts the XML from the CMS SignedData. **The signature is not verified**, and the page says so.
- Formats FPR12 (private parties), FPA12 (public bodies) and FSM10 (simplified), namespaces with or without prefix, several bodies per file. XML is read with `DOMParser` (no external stylesheets).
- Shows parties, general data (document type TD01-TD29, number, date, currency, reason, withholding, stamp duty, social security fund), references (orders, contracts, DDT), lines (quantity, price, discounts, VAT rate, nature N1-N7), VAT summary, totals and payment (terms, method MP01-MP23, due dates, IBAN). Code tables in Italian and English follow the public FatturaPA technical specifications, version 1.9.
- Attachments (Base64) are listed with name, format and size and can be downloaded. Print / save as PDF uses a dedicated print style with only the invoice; the XML extracted from a `.p7m` can be downloaded; the key details can be copied.

### VAT, VAT extraction & withholding tax (Italian)

![Italian VAT calculator](docs/screenshots/calcolo-iva.png)

A copyable invoice-style summary.

### Mortgage payment calculator (Italian)

![Mortgage payment calculator](docs/screenshots/calcolo-rata-mutuo.png)

![IBAN and VAT validator](docs/screenshots/iban-partita-iva.png)

## Favorites and custom menus

Every tool page and every home card has a star button; starred tools appear in a "Your favorites" section at the top of the home page and in a "Favorites" dropdown in the header, together with the custom menus (groups) you create. The management page (`/preferiti`, `/en/favorites`, `noindex` and not in the sitemap) creates, renames, deletes and reorders menus (drag and drop, or up/down buttons from the keyboard), adds tools with a search box, exports and imports JSON (preview, "merge" or "replace") and creates a share link whose data lives in the URL hash (`#d=…`, base64url of a compact JSON): it is never sent to the server, and opening it only shows a preview and asks for confirmation. Everything is stored in `localStorage` under `rrtools.favorites` (`{ v: 1, favorites: [ids], groups: [{ id, name, tools }] }`, at most 20 menus, names up to 40 characters), read only in the browser after hydration, validated on every read (unknown ids dropped) and synced between tabs with the `storage` event. If the storage is missing or full the app still works. The pure logic is in `src/app/core/favorites/` with its own tests.

## Keyboard shortcuts in the tools

Every tool page has the same shortcuts, driven by `data-shortcut` attributes on its buttons (no logic in the pages; `src/app/shared/shortcuts.ts` and `shortcuts.service.ts`): `Ctrl/⌘ + Enter` runs or generates, `Alt + Shift + C` copies the result, `D` downloads it, `S` swaps input and output, `X` clears (press twice to confirm), `O` opens "Send to…", and `?` (outside text fields) opens a help panel that lists only the shortcuts the tool really has. Esc closes panels and never clears data. Keys are read from `event.code`, so they work on macOS where Option changes the typed character. The "Shortcuts" button is hidden on touch devices.

## Share link

Most text and calculator tools (regex tester, diff, formatters, converters, calculators, generators…) have a "Copy link" button: the tool state (input text and options) is compressed (deflate), encoded in base64url and written in the URL hash (`#s=…`, versioned and per tool); opening the link restores it. The hash is never sent to the server, it is read only in the browser after hydration and validated per tool (types and allowed values, decompressed size capped at 256 KB, links over 8,000 characters are refused with a message). The URL is updated only when the button is pressed. Tools with passwords, keys, personal data or files (password generator and checker, TOTP, file encryption, htpasswd, JWT, hashes, certificates, tax code, IBAN/VAT, e-invoice, EXIF, PDF/image tools…) do not have it. The code is in `src/app/shared/share-state.ts` (codec and validation), `share-link.ts` (button) and one `<tool>.share.ts` schema per tool.

## Privacy

- **Everything runs client-side.** There is no backend: files are read and processed by your browser and are never uploaded.
- **No external requests.** No CDNs, web fonts or third-party scripts: everything is served from the same origin, and the Content Security Policy blocks connections to other servers.
- **No cookies, no tracking, no analytics scripts.** Only your theme, the dismissal of the "available in English" bar, your favorites and custom menus (`rrtools.favorites`: tool ids, menu names and order), the last tools opened from the Ctrl/⌘+K search (`rrtools.recent`: at most 5 tool ids, only if you turn the switch on in the Favorites page; it is off by default) and, if you use the Markdown editor, its draft are saved in your browser's `localStorage`; they are never sent anywhere.
- **Hosting.** The site is served by Cloudflare (hosting, content delivery and security), which processes the technical data of each request under its own privacy policy. There is no log system or analytics of my own, and no visitor counter.
- **Offline cache.** The site uses a service worker and the browser's Cache Storage only to keep the site files (pages, scripts, styles, fonts) so it works offline; nothing you enter in the tools is saved. You can empty it from the "Use offline" panel in the footer or from the browser settings.
- Full notice (Italian and English): [`/privacy`](https://tools.rrstudio.app/privacy) and [`/en/privacy`](https://tools.rrstudio.app/en/privacy).

## Smart paste and drop on the home page

The home page has a "Paste or drop here" box. Press `Ctrl/⌘ + V` anywhere on the page (outside a text field; in the search box and in any other field paste stays the normal browser paste) or paste into the box, and the content is recognised and the right tools are offered, most relevant first. Detectors (pure functions in `src/app/shared/content-detect.ts`, with many specs including false positives) cover JSON, JWT, URL, Base64, CSS colour, cron expression, IBAN, Italian tax code and VAT number (with checksums), SVG, curl and `docker run` commands, CSV/TSV, YAML, XML/HTML, SQL, Unix timestamp, UUID, hex hash (md5/sha*), PEM, IP/CIDR, Roman numeral, Morse code and dates. A short preview is shown as plain text only (never HTML; private key bodies are never shown) with the note that the content stays in the tab. A file can be dropped anywhere on the home page (a full-page overlay) or picked with "Choose a file": the type is read from the MIME type and the extension and tools are proposed (images, PDF, CSV, JSON/YAML/XML/SVG/text, PEM/CRT, and hash/encryption for any file); several files go only to tools that accept several. The content reaches the chosen tool through the in-memory "Send to…" service (`kind` text/json/csv/svg/image/files), so the receiving tools declare the kind in `HANDOFF_ACCEPTS`. Nothing is stored or uploaded. The mapping (`src/app/shared/smart-targets.ts`) is plain data and easy to extend.

## Share to the app and open files with it (PWA)

The manifest declares a Web Share Target (`POST` `multipart/form-data` to `/condividi/` with `title`, `text`, `url` and `files`) and file handlers (images, PDF, CSV, JSON, YAML, XML, PEM, text). When the installed app is chosen from the system share menu, the service worker intercepts the POST (`scripts/sw-share.mjs`, tested in `scripts/sw-share.test.mjs`; `build-sw.mjs` inlines it in `sw.js`), keeps the content **only in memory** and answers with a 303 redirect to the receiving page (`/condividi/`, or `/en/share/` when the first `Accept-Language` is English; `noindex`, not in the sitemap). The page claims the content with a message, once, and shows the same tool choice as paste and drop. Nothing goes to the Cache Storage or IndexedDB, and an unclaimed content is dropped after 60 seconds. Files opened with the app arrive through `launchQueue.setConsumer` on the same page. If the service worker is not active the POST reaches nginx, which answers 303 to the receiving page with a "try again" message without reading the body (`deploy/nginx.conf`).

## Install and offline use

The site is an installable PWA (`public/manifest.webmanifest`, icons generated by `npm run pwa-icons`) with a hand-written service worker, no libraries. `npm run build` runs `ng build` and then `scripts/build-sw.mjs`, which writes `sw.js` in the build root with a version (hash of the contents), a small precached SHELL (both home pages, main scripts, styles, fonts, icons) and the full list of pages and assets (including the pdf.js worker, the Web Workers and the password dictionaries) that the "Use offline" panel in the footer downloads on request. Pages are served network-first (3 s timeout) and fall back to the copy of the same page, then to a translated offline page; hashed files are cache-first and other same-origin files stale-while-revalidate. A new version waits until you press "Update"; requests to other origins are never touched. `npm run pwa-check` verifies it in Chromium (registration, offline navigation after the full download, offline page, update message).

I moduli sono bilingui e si precompilano solo con id dello strumento, lingua e indirizzo canonico della pagina: mai hash o query dell'URL (lo stato condiviso in `#s=` può contenere i tuoi dati) né quello che hai scritto nello strumento. Il sito non invia nulla; per inviare il modulo serve un account GitHub.

**Scorciatoie da tastiera negli strumenti.** Ogni strumento ha le stesse scorciatoie, guidate dall'attributo `data-shortcut` sui pulsanti (nessuna logica nelle pagine): `Ctrl/⌘ + Invio` esegue o genera, `Alt + Maiusc + C` copia il risultato, `D` lo scarica, `S` scambia input e output, `X` pulisce (due pressioni per confermare), `O` apre «Invia a…», `?` (fuori dai campi di testo) apre il pannello di aiuto con le sole scorciatoie presenti nello strumento. Esc chiude pannelli e menu e non cancella mai i dati. I tasti si leggono da `event.code`, quindi funzionano anche su macOS; il pulsante «Scorciatoie» è nascosto sui dispositivi touch.

**Incolla e trascina nella home.** Nella home il riquadro «Incolla o trascina qui» riconosce il contenuto e propone gli strumenti adatti: premi `Ctrl/⌘ + V` fuori dai campi di testo (nella ricerca e negli altri campi l'incolla resta quella normale) oppure incolla nel riquadro. I rilevatori (`src/app/shared/content-detect.ts`, con molti test anche sui falsi positivi) riconoscono JSON, JWT, URL, Base64, colori CSS, espressioni cron, IBAN, codice fiscale e partita IVA (con controllo del checksum), SVG, comandi curl e `docker run`, CSV/TSV, YAML, XML/HTML, SQL, timestamp Unix, UUID, hash esadecimali, PEM, IP/CIDR, numeri romani, Morse e date. L'anteprima è solo testo (mai HTML, il corpo delle chiavi private non si mostra) e ricorda che il contenuto resta nella scheda. Un file si trascina su tutta la pagina o si sceglie con «Scegli un file»: il tipo si riconosce da MIME ed estensione; più file vanno solo agli strumenti che li accettano insieme. Il passaggio usa il servizio «Invia a…» (solo memoria): niente viene salvato o caricato.

**Condividi con l'app e apri i file (PWA).** Il manifest dichiara un Web Share Target (POST multipart a `/condividi/`) e i gestori dei file (immagini, PDF, CSV, JSON, YAML, XML, PEM, testo). Il service worker intercetta il POST, tiene il contenuto solo in memoria e rimanda con un 303 alla pagina di ricezione (`/condividi/`, `/en/share/`, `noindex`, fuori dalla sitemap), che lo reclama una volta sola e mostra la stessa scelta degli strumenti; nulla va in cache o IndexedDB e dopo 60 secondi il contenuto non reclamato viene scartato. Se il service worker non è attivo, nginx risponde 303 alla pagina con l'invito a riprovare, senza leggere il corpo. I file aperti con l'app arrivano da `launchQueue`.

**Preferiti e menu personalizzati.** Ogni pagina strumento e ogni card della home ha una stella: gli strumenti scelti compaiono in cima alla home e nel menu «Preferiti» dell'intestazione, insieme ai menu personalizzati. La pagina `/preferiti` (`/en/favorites`, `noindex`, fuori dalla sitemap) permette di creare, rinominare, eliminare e riordinare i menu (trascinamento o pulsanti su/giù da tastiera), aggiungere strumenti con la ricerca, esportare e importare JSON (anteprima, «unisci» o «sostituisci») e creare un link di condivisione con i dati nell'hash (`#d=…`): non viene mai inviato al server e all'apertura chiede conferma. Tutto sta in `localStorage` (chiave `rrtools.favorites`, solo id degli strumenti, nomi e ordine dei menu).

- **Installazione:** `npm ci`, poi `npm start` per lo sviluppo e `npm run build` per la build
  statica (`dist/rrstudio-tools/browser`, pubblicabile su qualsiasi hosting statico).
- **Uso offline:** il sito è una PWA installabile con un service worker scritto a mano (nessuna
  libreria). Dal pannello «Usa offline» nel footer si scarica tutto per lavorare senza connessione; vengono
  salvati solo i file del sito, mai i dati inseriti negli strumenti. `npm run build` genera anche `sw.js`
  (`scripts/build-sw.mjs`); `npm run pwa-check` lo verifica nel browser.
